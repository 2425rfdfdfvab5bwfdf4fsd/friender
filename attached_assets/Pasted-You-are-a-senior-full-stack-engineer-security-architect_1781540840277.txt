Your mission is to upgrade this project into a more production-quality, safer, more useful version: PACCA v8.0.

Important rules:

1. Do not remove or bypass the security pipeline.
2. Do not create reverse shells, RAT-like features, exploit tools, credential harvesters, unauthorized scanners, or stealthy persistence.
3. Remote-control features such as WhatsApp, REST API, and WebSocket control must be authenticated, rate-limited, logged, and disabled or localhost-only by default.
4. Prefer safe defaults.
5. Preserve backward compatibility where possible.
6. Do not assume the README is accurate. Inspect the actual codebase first.
7. Every important change must include tests and documentation.
8. If something is risky, gate it behind config and explicit user approval.
9. If information is missing, choose the safest reasonable default and document it.

Phase 2: Security Hardening

Implement the following improvements if missing:

1. Authentication and session security
   - Add local admin token or login flow for REST/WebSocket access.
   - Bind to localhost by default.
   - Add explicit config for public exposure.
   - Add CSRF/CORS protections where relevant.
   - Add WebSocket origin validation.
   - Add rate limits for API, WebSocket commands, and WhatsApp webhook.

2. Safer remote integrations
   - WhatsApp webhook must verify signatures/tokens.
   - Remote commands must require a trusted user allowlist.
   - High-risk remote tasks must require explicit approval from a local dashboard unless configured otherwise.
   - Log all remote-origin commands clearly in audit logs.

3. Capability grant hardening
   - Ensure grants are single-use.
   - Ensure TTL expiry works.
   - Ensure tool name, task ID, args hash, user/session ID, and scope are bound into the HMAC payload.
   - Add tests for replay, tampering, expiry, and wrong-tool usage.

4. Path safety
   - Strengthen SafeResourceResolver.
   - Prevent path traversal.
   - Prevent symlink escape.
   - Prevent TOCTOU path swapping.
   - Normalize paths consistently.
   - Add property-based tests for path resolution.

5. URL/network safety
   - Validate URLs before browser/network tools.
   - Block localhost, private IP ranges, link-local IPs, file URLs, metadata service IPs, and redirect-to-private-IP cases.
   - Re-check after DNS resolution and after redirects.
   - Add tests for blocked URL patterns.

6. Audit log
   - Verify tamper-evident hash chaining.
   - Add `/api/audit/verify` if incomplete.
   - Ensure log permissions are `0600`.
   - Redact secrets before writing logs.
   - Add tests for redaction and hash chain verification.

7. Dangerous operations
   - Any destructive, irreversible, high-egress, or remote-control action must be risk-scored and approval-gated.
   - Add dry-run previews for file deletion, moves, writes, git commits, downloads, and workflow execution.
